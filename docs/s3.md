# S3-compatible access

Cupboard exposes a tenant's cache over the AWS S3 protocol with SigV4
authentication. [nixbuild.net] uses it to push build results directly (see
[nixbuild.md]). `nix copy` and other S3 clients can use the operations and
payload modes listed below.

This page describes the endpoint's shape and how to point generic tooling at it.
For the deployment settings (`S3_HOST`, `S3_SECRET_KEY`) and how credentials are
stored, see [nixbuild.md].

[nixbuild.net]: https://docs.nixbuild.net/settings/
[nixbuild.md]: ./nixbuild.md

## The cache as a bucket

The endpoint is not a general object store. Each tenant has one bucket:

- The bucket is the tenant slug. With path-style addressing the bucket is the
  first path segment, so a request goes to `https://<S3_HOST>/<tenant>/<key>`.
- A named cache is an object-key prefix; the default cache has no prefix.
- The keys are the Nix cache protocol's own: `nix-cache-info`, `<hash>.narinfo`,
  and `nar/<hash>.nar.zst`. A listing shows exactly these.

Only NAR and narinfo objects may be written. Cupboard stages a NAR until the
matching narinfo arrives, then verifies the NAR, signs the narinfo with the
tenant's key, and commits the path. It rejects every other object key.

## Credentials

Provision a credential scoped to the cache:

```console
$ cupboard s3-credential create https://cache.example.workers.dev/t/acme --label mirror
```

The command prints an access key ID and secret access key. It shows the secret
only once. Pass `--read-only` for a credential that can substitute but not
upload, `--cache <name>` to scope it to a named cache, and `--expires-at <iso>`
to give it a lifetime. Manage existing credentials with
`cupboard s3-credential list` and `cupboard s3-credential revoke`.

A public cache may be read without credentials, mirroring Cupboard's public-read
behaviour; writes always require one.

## Configuring a client

Use path-style addressing and any region (the endpoint does not interpret it;
`auto` is conventional). For example, with the AWS CLI:

```console
$ export AWS_ACCESS_KEY_ID=<ACCESS_KEY_ID>
$ export AWS_SECRET_ACCESS_KEY=<SECRET_ACCESS_KEY>
$ aws s3 --endpoint-url https://s3.cupboard.example.com --region auto \
    ls s3://acme/
```

`nix copy` speaks the same protocol. It takes the endpoint as a bare host with a
separate `scheme`, and addresses path-style by default. Pass `compression=zstd`:
the cache stores NARs as zstd and rejects any other encoding, whereas `nix copy`
compresses with xz by default.

```console
$ nix copy --to 's3://acme?region=auto&endpoint=s3.cupboard.example.com&scheme=https&compression=zstd' \
    /nix/store/<hash>-<name>
```

The public S3 endpoint requires HTTPS. Nix 2.33.3 sends `UNSIGNED-PAYLOAD` for
its uploads, so TLS protects the body while it is in transit. A local deployment
may use HTTP only when `CUPBOARD_LOCAL_DEV` is explicitly enabled.

Cupboard also accepts a fixed hexadecimal SHA-256 payload digest and
`STREAMING-UNSIGNED-PAYLOAD-TRAILER`. It verifies a fixed digest before it
returns success. It rejects the AWS streaming modes that use chained chunk
signatures because Cupboard does not verify those chunk signatures.

The narinfo PUT returns only after Cupboard has verified the NAR and committed
the path. Substitute the path with the cache's normal substituter URL and verify
its signature against the key at `/pubkey`.

## Supported operations

- Reads: `GetObject` (with `Range`), `HeadObject`, `HeadBucket`,
  `GetBucketLocation`, and `ListObjectsV2` (and v1) with `prefix` and
  continuation-token pagination. A listing enumerates `nix-cache-info`, the
  `<hash>.narinfo` keys and the `nar/<hash>.nar.zst` keys; a `delimiter` rolls
  matching keys up into common prefixes (for example `nar/`).
- Writes: `PutObject` for narinfo and NAR objects, and multipart upload for NAR
  objects.

Object deletion, `CopyObject`, and arbitrary non-cache writes are not supported.
ETags and `Last-Modified` are whatever R2 reports for a stored object; the
synthesised `nix-cache-info` carries a deterministic ETag and the cache's
creation time.
